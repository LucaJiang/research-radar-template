# 用 AI 建站、选文和维护

[English](ai-workflow.md) · [简体中文](ai-workflow.zh-CN.md) · [README](../README.zh-CN.md)

这些提示词可用于有仓库访问能力的 ChatGPT、Codex 或其他助手。复杂论文精读适合使用推理能力较强的模型，但网站不依赖某个具体模型名。改代码需要仓库读写，查新论文需要网页检索，全文解读需要 PDF 访问；缺少能力时应给出草稿或说明缺失权限，不假装已经完成。不要把密码或访问令牌放进提示词。

## 先准备研究画像

提供自己的仓库地址、托管方案、笔记语言、3–5 篇希望收录的代表论文及理由、2–3 个应排除的反例、研究问题、检索来源和时间窗口。再判断是否需要资源目录；它不是必选项。公开研究画像不要包含保密项目计划。

## 首次配置提示词

```text
请在我的仓库中工作：<自己的仓库 URL>。
它来自 research-radar-template。修改前请读 AGENTS.md、README.zh-CN.md、
site.config.json、src/data/topics.json、src/data/research-profile.json
和 docs/content.zh-CN.md。

研究领域：<领域>
核心研究问题：<问题>
应收录的论文及理由：<3–5 篇，附链接>
看似相关但应排除的论文及理由：<2–3 篇>
优先检索的原始来源：<来源>
检索时间窗口与时区：<窗口、时区>
笔记语言：<语言>
界面语言：<en 或 zh-CN>
每期最多篇数：<数量>
网站名称：<名称>
部署目标：<Cloudflare Pages / GitHub Pages / 其他>
已知的公开 origin 和 base：<网址、子路径；不知道可留空>
科研资源目录：<关闭 / 开启>
开启时的资源类型及字段：<类型、字段>

用我的范围替换虚构示例和通用研究画像，保留 Astro 静态输出、详细笔记、
日期、主题、归档、全文搜索、RSS、公式和移动端导航。文案可配置，内链支持
子路径。不要复制原作者的个人笔记或领域专有选文标准。静态网站不需要后端
数据库；如关闭资源目录，应从导航、生成路由和目录搜索条目中排除。

先给一小批候选，列出标题、实际发表／版本日期、原始链接、相关理由和全文
可访问情况，让我校准标准后再精读。不可编造访问情况或结果。获取不到 PDF
时，指出具体论文并请我提供。

我确认候选后，准备详细论文草稿和日报，执行 npm run build 和相关配置验证，
展示 diff 与检查结果。根据我的仓库和托管方案给出准确部署设置。
只有我已授权时才发布；不自行启用定时任务。
```

## 先校准选文，再精读

```text
收录 <论文 A>，因为 <理由>；排除 <论文 B>，因为 <理由>。
把这一区别写入研究画像，并按真实研究相关性重新排序其余候选，
不要只依据关键词、期刊声誉或新近程度。
```

```text
我确认精读：<论文清单>。这里是全文 PDF：<文件>。
按我提供的版本阅读，逐篇说明研究问题、方法和假设、验证设计、
带单位与不确定性的实证结果，以及具体局限。区分作者发现和你的推论。
引用真实来源，保留原始图号，只使用已核验且允许复用的图片。
分别记录发表日期、版本日期和日报日期。将草稿保存到
src/content/papers 与 src/content/daily，并说明无法核验的内容。
```

## 确认发布提示词

```text
我已审阅并同意把 <论文／日报日期> 发布到我的仓库。
设置相应论文与日报的发布标记，运行 npm run build，检查最终 diff，
提交并推送到已配置的生产分支。核对托管平台对应 commit 的部署状态，
并检查论文、主题、搜索和 RSS。分别报告 Git 提交与网站部署是否成功。
```

如果没有仓库或托管写入能力，应说明阻塞点并提供可审阅补丁。构建成功、提交成功都不能直接称为网站部署成功。

## 日常维护提示词

```text
根据我的研究画像，为 <日期> 查找过去 <N> 天的论文，按 <时区> 判断时间窗口。
与现有 DOI、标题和版本记录比较并去重，只给 <N> 篇高度相关候选，
附原始链接与全文可访问情况。我确认后再发布；没有合适内容就明确说没有，
不要为了凑数收录。
```

```text
使用这个新版本更新 <论文 ID>：<PDF 或来源>。
保留原 ID 和首次发表日期，更新版本名与日期，说明实质变化，检查相关日报
日期，保留有效的历史引用。不要把旧结果当作今天的新发现。
```

```text
为 <领域> 开启可选资源目录，分类与字段采用：<清单>。
核验官方来源、访问条件、覆盖范围和版本；按该领域定义字段，不强制遗传学
专有列。未知信息标注未知。先整理供我审阅，确认后再加入会公开的资源 JSON。
运行构建，检查资源搜索和锚点。
```

```text
关闭独立资源目录，保留论文、日报和日报中的研究简报。
确认资源导航、路由和目录搜索条目都不再生成，同时说明这不会擦除 Git 历史
中的源文件。
```

## 自动化是单独的选择

模板没有定时搜论文或 AI API 集成。Git 推送可以自动部署已经整理好的内容。
后续需要每日检索时，另行明确检索来源、运行环境、API 权限与费用约束、去重、
时区和人工审核规则。可先让自动化产生日报草稿或 PR，不默认授权无人审核发布。
